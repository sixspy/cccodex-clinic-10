# 编码清洗（clinic-10）败例清单与定边记录

> 本题只看「编码清洗」：访视行 visit_code/载荷空洞被标成 `编码空` 仍能入库、字段质控扫描漏网、对账矩阵编码列空洞。

## 一、动笔前败例清单（任一发生即判失败）

1. **缺落点仍收工**：编码清洗没有真正的落库表（凭证/快照），只在内存或前端打标，空码行依旧可入库。
2. **徽标亮但缺落点**：字段质控页清洗徽标点亮，却查不到对应的清洗落点行（凭证行），徽标与业务库对不上。
3. **指纹不符仍放行**：提交的清洗载荷与指纹核出的内容不一致（或库内行被偷改后指纹对不上），清洗仍然成功/入库门仍然放行。
4. **多余骨架残留**：甲乙两套读引用同时挂在字段质控页（双开），或存在可写入的第二套落点表/第二条活跃读路。
5. **整笔落库失败说不清**：凭证插入、访视行回写、发现关闭不在同一事务里，中途失败留下半笔脏数据，且没有明确错误返回。
6. **空码入库挡不住**：无有效清洗凭证的 `编码空` 行，经「合格入库」、行状态手改、补采成功任一路径变成 `已入库`。
7. **争用双成功冲掉钉点**：两个同事对同一行并发提交清洗，不加唯一钉点时双双成功、互相覆盖；落地方必须用数据库唯一键 + 事务让第二笔明确失败。
8. **徽标与空码条数拧花**：页上清洗徽标数与业务库空码条数/凭证数无法对账，数字对不上却不拦截。
9. **页面串不起来**：字段质控页（徽标+清洗队列）、访视批次页（空码条数）、缺口补采页（空码摘要是否进队列）、台参数（清洗口径）缺任一处接线。
10. **无头脚本交卷**：最终只靠 headless 脚本自证；须以页面白话指标对照业务库实际行验证。

## 二、甲乙两侧工程形态评估

### 甲侧：编码清洗凭证表（voucher ledger）
- 为每次清洗落一张**凭证表**：`row_id` 唯一钉点（当场键锁死，一行只允许一张凭证），凭证内含**指纹**（原始载荷摘要 + 清洗后载荷摘要 + 行键 + 批次）。
- 凭证一旦写入即**封档**：无 update/void 接口，读侧只读本张凭证；任何后续判断（入库门、徽标）只认这张凭证，拒绝回刷。
- 入库门改为：`编码空` 行必须能在凭证表读到**指纹核验通过**的本张凭证，否则拒绝入库。
- 争用：`UNIQUE(row_id)` 让并发第二笔在 INSERT 处撞约束失败，钉点不会被彼此冲掉。
- 语义匹配度：清洗是「对一个已存在缺陷行的一次性纠偏裁决」，凭证/封档/指纹正是一次性裁决的天然形态。

### 乙侧：编码清洗快照表（snapshot header + token）
- 开快照表，写入令牌（token）核妥后，现行读侧改绑该快照表头，读引用分叉。
- 快照是「整表/整批某时刻的只读副本」语义，适合报表分叉，不擅长表达「单行一次性裁决 + 拒绝回刷」；令牌核妥与读侧重绑会引入第二套活跃读路，与「禁双开、多余骨架拒绝交卷」天然冲突。

### 定边：**采用甲侧（凭证表）**
- 唯一钉点 + 指纹 + 封档 + 入库门单读路，直接覆盖败例 1/2/3/4/6/7。
- 乙侧不建表、不写服务、不留可执行代码与可写路由；本文件仅保留评估记录（设计说明，非骨架），字段质控页只有一套读引用。

## 三、落点核验顺序（交卷前逐项过）
1. 凭证表 `code_cleanse_vouchers` 存在且每个被清洗 row_id 恰有一行（落点入表）。
2. 凭证行含指纹，库内行内容与指纹重算一致才放行（封存档可反复核验）。
3. 页面空码条数 = 业务库 `quality='编码空'` 行数；徽标数 = 凭证表封档行数。
4. 对任一仍为 `编码空` 的行尝试三条入库路径，全部被拦。
5. 并发两笔清洗同一行：只成功一笔，第二笔明确报错且无覆盖。

## 四、交卷核验结果（2026-11-23 实跑）

- 落点入表：HTTP 实跑后 SQLite 实查 `code_cleanse_vouchers` 封档 1 行、row_id 唯一；全表清单无任何 `*snapshot*` 表（乙侧零骨架）。
- 封存档：凭证只有 INSERT/SELECT，`grep` 全仓无 `UPDATE/DELETE code_cleanse_vouchers` 写口；详情接口返回旧载荷→新载荷→旧指纹→封档指纹→令牌完整串。
- 指纹：正常清洗 `verified=true`；库内偷改载荷后 `verified=false`、徽标 `badge_consistent=false`、再走入库被明确拒绝。
- 白话对照：页面 API 空码 2 / 待清洗 2 / 封档 1，与 SQLite `COUNT(*)` 完全相等；对账矩阵新增「编码空」「封档清洗」两列，报告摘要含「空码无清洗凭证2 · 封档凭证1」。
- 三路径拦截：手改状态 400 报错、批次入库 `blocked_empty_code=[8]`、补采执行置「失败」并写拦截消息。
- 争用：双线程并发清洗同一行，结果 1 成功 1 报「编码清洗争用」，同行凭证恰 1 张、钉点内容未被覆盖。
- 整笔事务：非法输入（空编码/空载荷/坏 JSON/非对象）全部在写凭证前报错，凭证表零增长；专项测试 `tests/test_code_cleanse.py` 11 条 + 全量 18 条全绿，pyflakes 干净。
