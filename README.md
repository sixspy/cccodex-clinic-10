# cc-clinic-lab · 临床试验访视采集台

数据工程产品线基线。题号前缀 `clinic-*`，默认端口 **7600**。

## 技术栈

- 后端：CherryPy + SQLite
- 前端：原生 JS SPA（顶栏薄荷绿丝带导航）
- 会话：itsdangerous 签名 Cookie
- 测试：pytest + httpx（依赖已列入 requirements）

## 登录

- 地址：`http://127.0.0.1:7600/login`
- 账号：`admin` / `123456`

## 页面

| 页面 | 能力 |
|------|------|
| 试验中心 | 中心登记、启停/观察、配额、方案版本生效 |
| 访视批次 | 开批、模拟抓取、追加访视行、合格入库、收齐/关闭、空码条数展示 |
| 字段质控 | 按批/全量扫描、发现关闭/重开、编码清洗封档凭证、清洗徽标对照空码条数 |
| 缺口补采 | 排队、执行成功/失败、失败重试；编码空行补采入库被闸门拦截 |
| 访视对账 | 缺口/发现/补采对照、中心矩阵（含编码空列与封档清洗列）、审计 |
| 台参数 | 设置读写，含编码清洗口径 `code_cleanse_rule` |

## 编码清洗（甲侧 · 封档凭证）

编码空行不能直接入库，必须先在字段质控页提交编码清洗，落 **甲侧凭证表** `code_cleanse_vouchers`：

- 一行一张凭证，`row_id` 唯一钉点；并发争抢时数据库唯一约束保证只成功一笔，第二笔明确报错，钉点不被冲掉。
- 凭证挂 SHA-256 指纹（批次+受试者+清洗后访视编码+载荷+质量），凭证只有 INSERT/SELECT，无 update/delete 写口，封档只读、拒绝回刷。
- 入库闸门（手改状态 / 批次合格入库 / 补采成功三条路径）：编码空行无封档凭证、或持凭证行指纹核验不符，一律拒绝入库。
- 清洗提交与访视行回写、发现关闭在同一事务，整笔失败整体回滚，不留半笔。
- 字段质控页清洗徽标与业务库空码条数严格对账（`空码总数 == 待清洗数` 且无失效凭证）；乙侧快照表不建表、不留骨架，全系统只有凭证表一套读引用。
- 设计与败例清单见 `docs/code-cleanse-plan.md`，专项测试见 `tests/test_code_cleanse.py`。

## 主链

中心 → 访视批次抓取 → 质控发现 → 缺口补采 → 对账报告；设置与审计贯穿写操作。

## 本地

```powershell

pip install -r requirements.txt
pytest
python run.py
```

Docker：`docker compose up -d --build`，健康检查打 `/login`。
